*** Ledyer Payments for WooCommerce Changelog ***

2026.11.11      - version 1.0.4
* Fix           - If creating the Ledyer order fails after the payment is authorized, the plugin now tries again on the order confirmation page and from Ledyer's authorization webhook, so the WooCommerce order no longer ends up without a Ledyer order.
* Fix           - The authorization webhook is now handled right away and returns an error when processing fails, so Ledyer can retry it.
* Fix           - The billing country sent when creating the Ledyer order is now taken from the order, so it is also correct when the order is created from the webhook.
* Fix           - Only one request at a time can confirm an order, which stops the confirmation page and the webhook from processing the same order twice.
* Fix           - Customers are now sent to the order confirmation page when creating the Ledyer order fails, instead of seeing an error that could lead them to pay again.
* Tweak         - An order note is added when the Ledyer order could not be created, and another when it was later created successfully.
* Tweak         - Updated the krokedil/wp-api dependency to 1.2.2, so the correct user agent is sent to Ledyer.

2026.10.15      - version 1.0.3
* Fix           - Re-release of 1.0.2 to WordPress.org.

2026.10.15      - version 1.0.2
* Tweak         - Orders now stay On hold until Ledyer has confirmed the payment and marked the order ready for capture, aligning order status handling with Ledyer Checkout.

2026.08.11      - version 1.0.1
* Tweak         - Security level handling is now managed by Ledyer and the security level option has been removed from plugin settings.

1.0.0
* Initial release.
